# Working material

Design conversations, adoption reviews, research comparisons and superseded roadmaps — the material the committed designs were distilled *from*. Kept because the reasoning is worth keeping; deliberately not part of the documentation site, because it records how decisions were reached rather than what was decided. The distilled results live in [`docs/`](../docs/), which is the site.

Two of these are specifications rather than conversations, and both have had their first phase built — so a reader picking them up should know which parts are now code and which are still design. [Persistent components and online change](source-rpc-online-change-design/source-rpc-online-change-design-spec.md): Phase 1, snapshots and held-state migration, is `@source-repo/continuity`; the managed runtime, consistent capture and fenced replacement are not built, and `admissibleForHandoff` refuses rather than letting that be discovered at a barrier. [Node live diagnostics](source-rpc-node-live-diagnostics-design/source-rpc-node-live-diagnostics-design-spec.md): Phase 1, source-linked props and state, is `@source-repo/diagnostics` and the console's source view; instrumented variants, tracepoints, breakpoints and stepping are not, and every one of them is advertised as `false` rather than omitted. The specs are unedited — their status lines describe what was ready to build when they were written, not what has since been built.

Also here: field-trial feedback, starting with [the first fresh-agent session](session-feedback-2026-08-01.md) — a Claude with no prior knowledge of the project working the network through the MCP server, whose findings were filed into Linear.

# Working material

Design conversations, adoption reviews, research comparisons and superseded roadmaps — the material the committed designs were distilled *from*. Kept because the reasoning is worth keeping; deliberately not part of the documentation site, because it records how decisions were reached rather than what was decided. The distilled results live in [`docs/`](../docs/), which is the site.

Two of these are specifications rather than conversations, and both have been built past their first phase — so a reader picking them up should know which parts are now code and which are still design. [Persistent components and online change](source-rpc-online-change-design/source-rpc-online-change-design-spec.md): Phases 1 to 3 are `@source-repo/continuity` — snapshots and held-state migration, then the managed runtime, consistent capture and the obligation manifest, then shadow activation, ownership epochs and fenced replacement — along with the portable form and the C# reader that Phase 4 turns on. What is not built is Phase 4's journal and replay-assisted recovery, which is what `failed-after-commit`'s *recover forward* would need to be a procedure rather than an instruction. [Node live diagnostics](source-rpc-node-live-diagnostics-design/source-rpc-node-live-diagnostics-design-spec.md): Phase 1, source-linked props and state, is `@source-repo/diagnostics` and the console's source view. Phase 2 is built as far as its telemetry — a variant can be proved a derivative (`admissibleVariant`, with the strip in `@source-repo/rpc-cli`), generated (`instrumentSource`), given somewhere to write (`RpcProbeSink`), and swapped in and out over continuity's `handOver`, which is section 16 step for step. What is not built is the telemetry transport and the observation session and authority model that go with it, so probe samples stay in the process that produced them; nor are tracepoints, which are Phase 2's tail, nor breakpoints and stepping, which are Phase 3. Those are advertised as `false` rather than omitted, and the capability set is now derived from what a host actually wired rather than declared, so a node that has no coordinator says so. The specs are unedited — their status lines describe what was ready to build when they were written, not what has since been built.
